# Python の、ファイルの中だけで使う関数と定数の名前（すべてのプロジェクトのためのルール）

- Python のファイルを書くときは、そのファイルの中でしか使わない（ほかのファイルから使う予定がない）関数の名前の先頭に、`_` を付ける。
  - 例: `_dispatch_call_to_robot()`、`_wait_until_robot_accepts()`、`_execute_queued_actions()`。
  - 理由: 「このファイルの中だけで使う」という意図を、名前で読み手に伝えるため（可読性）。2026-10-23 にユーザーが「徹底してほしい」と指示した。
- 次の関数には、`_` を付けない。ファイルの外から使われるためである（Claude の解釈。2026-10-23 にユーザーが確かめた形）。
  - ほかのファイルから import して使う関数。
  - ほかのプロセスが URL を通して呼ぶ関数（FastAPI の `@app.get` や `@app.post` を付けた関数など）。
  - 起動の入り口（`main()` など）。
- クラスの中でしか使わないメソッドにも、同じく `_` を付ける（`_request_command_if_ready()`、`_build_controller_url()` など）。
- そのファイルの中でしか使わないモジュールの定数は、そのファイルの中に定義し、名前の先頭に `_` を付ける。
  - 例: `CAMERA_INDEX` → `_CAMERA_INDEX`、`CARE_PERIOD_SEC` → `_CARE_PERIOD_SEC`。
  - 理由: 2026-11-04 に、ユーザーが「ファイル内でしか使わない定数はそのファイル内に定義し、名前の先頭に _ をつけるようにして下さい」と指示した。関数と同じく、「このファイルの中だけで使う」ことを名前で伝えるため。
  - 例外: ほかのファイルから import して使う定数（コメントにしたコードの中で import しているものも含む）には、`_` を付けない。
  - 例外: プロセス間の取り決めを1つのファイルにまとめる決定（ADR など）がある定数は、使うファイルが1つでも、そのファイルに置いたままにする。
  - 定数の値を環境変数から読むときは、Python の名前だけを変え、環境変数の名前（文字列）は変えない（例: `_ROBOT_PORT = os.environ.get("ROBOT_PORT")`）。
- 既存の関数と定数の名前を変えたら、その名前を書いたコメント、説明、文書も、あわせて直す。
- ほかのファイルから使っているかは、名前を変える前に、リポジトリ全体を検索して確かめる。
