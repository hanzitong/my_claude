# Claude が書く日本語の文書の書き方（すべてのプロジェクトのためのルール）

このルールは、Claude が日本語の文書（仕様書、設計書、ADR、実装の記録、README、ルール、スキル、エージェント、CLAUDE.md など）を書くとき、直すときに当てはめる。

- 文書でも、`~/.claude/rules/japanese-reply-style.md` の決まりに従う。特に、次の4つを守る。
  - 日本語を、論理的に、誤解がないように書く。
  - 動詞を使うときは、その動作主（主語。誰が、何が）を書く。
  - 動詞を使うときは、できるだけ、その修飾語（どこに、どこから、何を、いつ、どのように）も書く。
  - 説明の前に、前提を説明する。読み手を、その話について何も知らない、外から来た人だと思って書く。
  - 理由: 2026-11-03 に、ユーザーが「この日本語関連の注意点は、ドキュメント作成時の注意点としても書いておいて下さい。とても重要なので」と指示した。
- 文書では、前提を、文書や節の冒頭に置く。前提として、何の話か、登場するもの（プロセス、ファイル、関数など）、それぞれの役割、いまどういう状況か、を整理して書く。そのあとで、本題を書く。
  - 例外: 文書の冒頭に「この文書について」がすでにある文書は、その節を前提として使う。この例外は Claude の解釈であり、ユーザーには確かめていない。
- 文書の種類ごとの決まり（書く先、ADR の構成など）は、プロジェクトのルールとスキルにも従う。
