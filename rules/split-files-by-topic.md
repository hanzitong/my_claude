# 文書は、話題ごとにファイルを分ける（すべてのプロジェクトのためのルール）

- 文書を作るとき、直すときは、理由なく、別々の話題を1つのファイルにまとめない。
  - 対象: ルール、スキル、エージェント、CLAUDE.md、仕様書、設計書、README などの文書。
  - 理由: 2026-11-02 に、Python と C++ の名前のルールを1つのファイルにまとめたところ、ユーザーから「コーディングの注意点は言語ごとに分けていたので、分けてほしい」と言われた。ユーザーは、今後の文書の作成と修正でも、これを大事にしてほしいと指示した。
- 書き足す前に、既存のファイルがどう分かれているか（言語ごと、話題ごとなど）を確かめ、その分け方に合わせる。
- 書き足す内容に合うファイルがなければ、既存のファイルに混ぜず、新しいファイルを作る。
- 複数の話題に共通する内容は、1つのファイルにまとめてよい。各話題のファイルからは、そのファイルを参照する。
  - 例: コードのレビューで名前を確かめることは、言語に共通なので、`code-review-names.md` の1つにまとめた。
