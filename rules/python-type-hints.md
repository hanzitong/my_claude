# Python の型ヒント（すべてのプロジェクトのためのルール）

- Python のコードを書くときは、型ヒントを必ず付ける。
  - 理由: 2026-11-03 に、ユーザーが「型ヒントを必ずつける」ことを、まず意識してほしい点として指示した。
  - 例外: 文法の上で、その行の中に型ヒントを書けないところ（`for` の変数、`with ... as` の変数、`except ... as` の変数、複数の値を一度に受け取るときの変数、内包表記の変数、`:=` の変数、ラムダの引数）。型が読み手に分かりにくいときは、前の行で `captured_frame: np.ndarray` のように宣言してもよい。この例外は Claude の解釈であり、ユーザーには確かめていない。
  - 例外: `self` と `cls`（文法の上では書けるが、慣習に合わせて付けない）。この例外は Claude の解釈であり、ユーザーには確かめていない。
- 型ヒントは、次の場所に付ける。
  - 関数とメソッドの、すべての引数。
  - 関数とメソッドの戻り値（何も返さないときも `-> None` と書く）。
  - モジュールの定数（例: `CARE_PERIOD_SEC: float = 1.0`）。
  - ローカル変数（最初に値を入れる行で付ける。例: `received_vlm_answer: str = ...`）。
  - インスタンスの属性（`__init__` などで、最初に値を入れる行で付ける）。
  - ローカル変数とインスタンスの属性に付けることは、Claude の解釈であり、ユーザーには確かめていない（このユーザーの既存のコードは、ローカル変数にも付けている）。
- 型ヒントは、次のように書く。Python 3.10 以上を前提とする。この書き方は Claude の解釈であり、ユーザーには確かめていない。
  - 組み込みの型で書く（`list[str]`、`dict[str, int]`、`tuple[bool, int]`。`typing.List` などは使わない）。
  - 値がないことがあるときは、`X | None` と書く（`Optional[X]` は使わない）。
  - `Any` は、外部のライブラリの値のうち、型を書けないものにだけ使う。
- コードを点検するときは（ユーザーに頼まれたレビュー、`/code-review`、Claude が自分で書いたコードの見直しの、どれでも）、型ヒントのない引数、戻り値、定数、ローカル変数、インスタンスの属性を、ファイル、行、型の案を添えて指摘する。直すかどうかは、プロジェクトのルールにも従う。
