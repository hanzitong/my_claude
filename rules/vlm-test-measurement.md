# VLM の計測（ROBO_NEXT のためのルール）

VLM のモデルの精度と速さの検証は、vlm_test の役割である。robo_system の側では行わない。

- 処理時間は、time.perf_counter() で測る。
- モデルのロードの時間と、1回の推論の時間を、分けて記録する。
- 1回目の推論の値は、集計から除くか、ほかと分けて書き、どちらにしたかを書き添える。
  - 理由: 1回目の推論は、ウォームアップの影響で長くなることがある。
- 同じ条件で複数回測り、平均だけでなく、中央値と最大を書く。
  - 理由: ロボットの振る舞いを決めるのは、最大の遅れである。
- 計測の条件として、日付、モデルの名前、モデルの量子化、GPU、画像の枚数、画像の大きさ、プロンプト、生成の設定（最大トークン数など）を書く。
- 条件が違う結果を並べるときは、そのまま比べられないことを書き添える。
- 正解と比べるときの判定の基準（完全一致か、意味が合えばよいか）を、先に決めて書く。
- 判定に迷う行は、判定せずに一覧にする。
- 測った値と、見込みの値を区別する。

出典: Python の time（perf_counter）https://docs.python.org/3/library/time.html 、ROS 2 のリアルタイムの設計（最大の遅れとばらつき）https://design.ros2.org/articles/realtime_background.html
