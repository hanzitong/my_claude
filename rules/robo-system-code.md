# ROBO_NEXT のコード（ROBO_NEXT のためのルール）

- Claude は、ユーザーが頼まない限り、コードを変更しない（読む、解説する、指摘する、提案する、までにとどめる）。
  - 理由: 2026-10-13 から、コードはユーザーが自分で書く。
  - 全プロジェクト向けのルール（`~/.claude/rules/` の名前、型ヒント、1行だけの関数など）で直すべき箇所を見つけたときも、ROBO_NEXT のコードは、ユーザーに頼まれたときだけ直す。
- 直したほうがよい箇所を見つけたら、ファイル、行、直し方を文章で伝える。
  - 例外: 伝えたあとで、ユーザーが改めてその変更を頼んだときは、ユーザーに頼まれた範囲だけを変える。
  - 例外: コメントと docstring の、古い記述や間違った情報は、見つけたらその場で直し、直したことを伝える（2026-11-04 のユーザーの指示。`robo-system-docs.md` を参照）。コードの振る舞いは変えない。
- Bash での書き込み（リダイレクト、`sed -i`、`cp`、`mv` など）や、作業ツリーを変える git の操作でコードを変えることも、変更に当たる。
- ユーザーの頼みで robo_system のコードを書くときは、外観だけを書き、外観以外の中身は `raise NotImplementedError` にする。
- 外観とは、関数の名前、引数、戻り値、説明と、スレッドに関する処理（生成、開始、停止、繰り返し、Lock や Event による共有データの読み書き）である。
- 外観だけを書いた関数で、中身が `raise NotImplementedError` だけのものは、中身が1行だけの関数を禁じるルール（`~/.claude/rules/python-no-one-line-functions.md`）の例外とする。中身を書くまでの仮の形であるため。この例外は Claude の解釈であり、ユーザーには確かめていない。
- 基礎関数を定義したファイル（`robo_system/src/robo_system/robot_primitives.py`、`speaker_primitives.py`）が、仕様書や設計書と食い違うときは、このファイルを正とする。
  - 理由: このファイルは、ユーザーが書く。
- コードを読むときは、`~/.claude/rules/robotics-runtime.md` の観点でも見る。
