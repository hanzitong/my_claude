頼まれた範囲の最小構成で作る。「あると便利」という理由だけで、頼まれていない機能・設定・ファイルを追加しない。追加したい場合は実装せず、提案として伝えて判断を任せる。

**Why:** 2026-10-07、robo_system パッケージ作成時に `[project.scripts]` の起動コマンドと `main()` ラッパーを独断で追加したところ、ユーザーから「コードベースは把握できる大きさなので不要。便利だと思って追加しても私にとって混乱する原因になる」と指摘された。ユーザーは Python のパッケージ構成や Claude の機能を学びながら進めており、自分が理解していない仕組みが増えることを嫌う。

**How to apply:** 新規作成やリファクタリングでは、依頼を満たす最小限だけを書く。コピーを頼まれたら、動作に必須の変更（例: 相対 import）以外は手を入れない。テスト、CLI コマンド、設定の分割などを足したくなったら、返答の中で1行の提案にする。関連: [[project-config-in-project-dir]]
