# robo_system パッケージの目的

`robo_system/` の目的は、**システムアーキテクチャを検討すること**です。
デモ用の完成品を作り込む場所ではありません。

- 検討の対象は、プロセスの構成（camera_process、vlm_process、robot_action_process など）、プロセス間のやりとり、状態やスレッドの持ち方です。
- 提案や変更は、アーキテクチャの検討に役立つかどうかで判断してください。
- 製品化のための作業（エラー処理の作り込み、設定の外出し、CLI、テストの充実など）は、頼まれない限り入れないでください。

# 設計の文書と、ADR

`robo_system` の設計に関する文書は、次のように使い分けます。

| 文書 | 場所 | 内容 |
|---|---|---|
| 基本仕様書 | `robo_system/specifications/01_basic_specification.md` | 何を満たすべきか（全体）。目的、概要、機能の一覧、動作環境、前提と制約 |
| 詳細仕様書 | `robo_system/specifications/02_detailed_specification.md` | 何を満たすべきか（機能ごと）。振る舞い、システムの状態、基礎関数、品質の目安 |
| 基本設計書 | `robo_system/specifications/03_basic_design.md` | どう実現するか（全体の構造）。プロセスの構成、通信方式、スレッドの構成、状態の管理 |
| 詳細設計書 | `robo_system/specifications/04_detailed_design.md` | どう実現するか（内部の作り）。API、共有するデータ、処理の流れ、関数の一覧、仮の数値 |
| 実装の記録 | `robo_system/docs/implementation/05_implementation_notes.md` | 実装して、動かして、分かったこと。試験の記録、計測した値、まだ文書に反映していないこと |
| ADR | `robo_system/ADR/` | アーキテクチャレベルの設計判断。選択肢、比較、理由 |
| 管理台帳 | `robo_system/ADR/INDEX.md` | ADR の状態、ADR 同士の関係、更新の記録。設計の新旧は、ここで管理します |

- 実装の記録に書いたことは、まだ決定ではありません。議論して決まったら、仕様書、設計書、ADR に書いて、実装の記録からは消します。
- ADR の書き方と、設計書との揃え方は、`adr` スキル（`~/.claude/skills/adr/SKILL.md`）に従ってください。
- ADR に書くのは、アーキテクチャレベルの決定だけです。プロセスの分け方、プロセス間の通信方式、スレッドの分け方、状態の持ち方が、これに当たります。
- 仕様書と設計書には、古い情報を残しません。設計が変わったら、新しい内容に書き換えます。以前の設計と、変えた理由は、ADR と管理台帳でたどります。
- アーキテクチャの相談を受けたときは、提案の前に管理台帳を読み、状態が「採用」の ADR と矛盾しないかを確認してください。
- `robo_system/src/robo_system/` のコードは、外観だけを書きます。関数と、スレッドに関する処理の骨組みまでで、詳細の実装には、頼まれない限り進みません。
